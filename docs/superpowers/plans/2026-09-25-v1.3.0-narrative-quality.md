## 一、需求文档（R）

### 背景

v1.2.0 完成了骨架参数化与 120 回合零失败验收，但四题材 30 回合的量化数据暴露了
三个剧情质量缺口，加上一个历史 gate 遗留：

| 缺口 | 实测证据 | 玩家影响 |
|---|---|---|
| 结局层模板残留 | AI 草案世界的结局 ID/narrative_key 直接继承雾港骨架（`fog-drowned`/`ending.fog_drowned`），`_rename_story_surface` 只重写章节/选择/路线，不碰 endings | 每个自创世界的结局都是同一套"雾港"语义的换皮；诊断导出里可见内部模板 ID |
| 回合开头惯性 | 单世界同一开头句式最多 8/30 回合（survival"通风口内，杰克继续…"）；v1.2.0 的 recent_openings prompt 约束未实测复验 | 长局阅读疲劳，"每回合都像同一个故事" |
| 战斗反馈单薄 | 反馈条只有一行文字，无掷骰明细与 HP 变化呈现；战斗按钮无可用性区分（可攻击目标 vs 已倒下仅文字尾缀） | 战斗作为核心卖点（d20 引擎）在 UI 上感知弱 |
| Director 注释黑盒 | ADR-012 已实现注入，但 director_notes 无任何可视化，质量无法评估，参数（间隔 6 回合/温度 0.3）无法调 | 无法判断 Director 是增强还是噪音 |

### 目标

让"自创世界玩 30 回合"的剧情体验达到：结局有题材个性、回合开头不重复、
战斗有 dice 感、Director 的作用可见可调。对应评分矩阵：玩家体验 8.3 → 8.5、
UI 设计 8.0 → 8.5、功能完整度维持 8.5。

### 用户故事与验收标准

| # | 用户故事 | 验收标准（可测） |
|---|---|---|
| R1 | 作为玩家，我完成自创悬疑世界时，结局的内部标识与展示不应残留"雾港"模板词 | 四题材草案生成后：endings 的 `id`/`narrative_key`/展示标题互不相同且不含 fog/lan_dawn 等模板词；契约校验通过；诊断导出无模板 ID 泄漏 |
| R2 | 作为玩家，连续游玩 30 回合，每回合的叙事切入方式应有变化 | 重跑任一题材 30 回合：开头 24 字重复 <5/30（v1.2.0 实测 survival 20/30、mystery 8/30）；recent_openings 约束 + 相似度度量双落地 |
| R3 | 作为玩家，我发起攻击时能直观看到掷骰与伤害的因果 | 攻击反馈条显示 d20 原始值 + 伤害 + 目标 HP 变化；击败目标时按钮转为倒下态并有视觉区分 |
| R4 | 作为维护者，我能评估 Director 注释是否提升剧情 | 30 回合长局导出包含 director_notes 全量 + 对应回合叙事；可人工抽查相关性 |
| R5 | 作为维护者，macOS 安装包窗口走查补齐 gate 遗留 | TCC 已授权；Tauri 窗口可见走查完成并截图存 eval |

### 非目标（1.3.0 不做）

- RAG 世界书 / TTS 语音（Wave3 大件，挪入 1.4.0+，与 9/24 AI 新产品会话的图像生成/语音 GM 方向合并排期）
- 先攻 initiative 排序（战斗内回合制重构，涉及 command_engine 语义扩展，单独 ADR）
- Android 端同步改造（PlayScene 为桌面组件；移动端沿用后端能力，UI 侧跟进放 1.3.x 补丁）
- 旧版 frontend/ 目录删除（归档保留，独立清理提交）

## 二、产品方案（P）

### P1 结局去模板化（对应 R1）

**体验设计**：结局卡新增一行"结局标题"（genre 化的展示名），替代目前只有
"好结局/坏结局"的 kind 标签。标题由 genre 骨架的结局模板生成：

| 题材 | 好结局标题示例 | 坏结局标题示例 |
|---|---|---|
| 悬疑探案 | 真相收网 | 冤案落定 |
| 灾难求生 | 黎明突围 | 长眠于此 |
| 政治阴谋 | 棋局易手 | 满盘皆输 |
| 蒸汽朋克西部 | 正午枪响 | 铁轨碾过 |
| 自定义回退 | 尘埃落定 | 步步失守 |

**规则**：结局 ID 与 flag 条件逻辑完全不变（引擎语义稳定）；只新增展示层
`title` 字段，由骨架按 kind + genre 生成，草案审阅页可见可改。

### P2 回合开头反惯性（对应 R2）

**体验设计**：玩家不可见。机制三层：

1. prompt 约束（v1.2.0 已做）：recent_openings + 严禁相似开头；
2. **相似度度量**（新增）：每回合落库时计算新叙事开头与 recent_openings 的
   4-gram 重叠率，写入诊断导出；
3. **后处理兜底**（新增）：重叠率 > 60% 时，截去新叙事与上一回合相同的开头
   短语（前 12 字内），强制从第二句起展示。

### P3 战斗反馈强化（对应 R3）

**体验设计**：

- 反馈条升级为三行结算卡：`⚔ 掷出 d20: 14（+3 调整值 = 17）→ 命中`、
  `伤害 1d10+2 = 7 → 哥布林头目 HP 14→7`、`目标状态：受伤`；
- 数据全部来自已有的 attack outcome（roll/hit/damage/target_hp/defeated），
  无需后端改动；调整值 = attack_bonus 从 combat.participants 读取；
- 被击倒目标的按钮保持倒下态（已实现），新增反馈条倒计时 10 秒后淡出。

### P4 Director 注释可见化（对应 R4）

**体验设计**：设置 → 高级诊断信息 下新增"Director 注释"折叠区：

- 显示当前 Run 最近一条生效注释（tension/hook/turn）；
- 历史注释列表（turn 倒序）；
- 开关：`启用 Director 节奏注入`（默认开，关停后不再调度且不注入）。

### P5 Tauri 窗口可见走查（gate 遗留）

解锁屏幕后：启动 DZMM.app（隔离数据目录）→ 走"世界 → AI 创作 → 草案 →
确认 → 游玩 5 回合"→ 全程截图存 `eval/score-upgrade/screens/tauri-walkthrough/`。

## 三、技术方案（T）

### T1 结局去模板化

**改动面**：

1. `genre_presets.py`：每个 preset 的 `skeleton` 增加 `endings` 模板——
   `{good: {title, …}, normal/bad/hidden: …}` 四类各含标题模式
   （如悬疑好=`真相收网`、坏=`冤案落定`）与一句 `epitaph`（结局卡副文）；
   `DEFAULT_SKELETON` 同步提供回退（`尘埃落定`/`步步失守`/`草草收场`/`真相未明`）；
2. `ai_world_drafts.py::_rename_story_surface`：新增 endings 重写段——
   保留骨架的 `when`/`priority`/效果语义，重写 `title`（新增展示字段）与
   `narrative_key`（改为 `ending.{genre}.{kind}`，genre 从 skeleton id 取）；
   `ending.id` 保持 kind 对应的稳定 ID（`good`/`normal`/`bad`/`hidden`），
   不再继承雾港名词；
3. 契约：`world_definition.schema.json` 的 endings items 增加可选 `title`；
   `run_state.schema.json` 的 ending 增加 `title`（可选，向后兼容旧存档）；
4. `story_beats.py` / 前端结局卡：优先展示 `ending.title`，回退 kind 文案。

**兼容性**：旧存档 ending 无 title → 前端回退 kind 文案，不迁移不报错。

### T2 回合开头反惯性

1. `core_runtime.py` 回合落库处：计算 `opening_overlap`（新叙事前 24 字 vs
   recent_openings 的 4-gram Jaccard），写入 turns 行新列 `opening_overlap REAL`
   （迁移 0014）或仅诊断导出（选后者，避免迁移）；
2. 后处理兜底：`narrative_output.clean_narrative_output` 增加可选参数
   `avoid_openings: list[str]`——若新叙事前 12 字与任一 opening 前 12 字相同，
   截去重复前缀（从第一个逗号/句号后开始展示）；
3. 验收脚本：`eval/score-upgrade/replay_opening_check.py`——30 回合重跑 +
   输出开头重复统计（目标 <5/30）。

### T3 战斗反馈强化

纯前端（后端 attack outcome 字段已齐：roll/hit/damage/target_hp/defeated）：

1. `PlayScene.vue` 反馈条改为结算卡：
   - 行 1：`d20 掷出 {roll}{±bonus} = {total} → {命中|未命中|要害!}`；
   - 行 2：`伤害 {damage} → {target.name} HP {before}→{after}`；
   - 行 3（defeated）：`{target.name} 已倒下`；
   - `before` = 攻击前快照（App.vue attackTarget 已有 participants 可读），
     `after` = outcome.target_hp；
2. `attack_bonus` 暴露：`state.combat.participants` 已含（T1 契约同步时确认）；
3. 击败淡出：反馈条 10s 后 opacity 过渡（CSS only）。

### T4 Director 可见化

1. `main.py` 新增只读端点 `GET /api/v2/runs/{run_id}/director-notes`（表已有）；
2. 设置 → 高级诊断 → "Director 节奏"折叠区：最近注释 + 历史列表 + 开关
   （开关存 localStorage，关闭时前端不显示且后端跳过调度——通过新查询参数
   `?director=off` 或运行时设置，选后者：`Settings.director_enabled: bool = True`）；
3. 长局评估脚本：`eval/score-upgrade/director_audit.py`——30 回合跑完导出
   (turn, tension, hook, 当回合叙事前 80 字) 四元组，供人工打相关性分。

### T5 Tauri 走查

纯执行项（TCC 已授权）：computer-use 驱动 + `screencapture`，检查清单 =
启动可见性 / 字体渲染 / 侧栏与结局卡布局 / 深浅主题切换 / 键盘可达性。

### 测试策略

| 层 | 用例 |
|---|---|
| 单测 | 骨架 endings 模板映射（各 genre 互异 + 回退）；narrative_key 重写；title 回退；draftGate 复归；opening 兜底截断 |
| 契约 | world_definition / run_state schema 变更后全量 validate |
| 集成 | 四题材草案生成 → endings 无模板词；30 回合重跑 → 开头重复 <5/30 |
| 手动 | Tauri 窗口走查（等解锁）；Director 面板抽查 |

### 风险

- 结局 title 进契约需向后兼容旧世界版本（可选字段 + 前端回退，已设计）；
- prompt 反重复约束对 7B 模型的遵循度未知——T2 的度量会给出量化答案，
  若无效则升级为后处理改写（1.3.x）；
- Director 开关放运行时设置需重启生效，UI 上注明。
