环境：v1.0.0 DZMM.app 内嵌 sidecar（127.0.0.1:8801，隔离数据目录）+ 远程 LM Studio

AI 草案 → compose → 逐回合（选项轮换 + 每 7 回合自由行动）。

## 好消息：叙事层零固化

- **跨世界 4-gram 重叠率 0.0%~1.0%**（六组两两对比）——四个小众世界的叙事
  几乎无重复，"所有世界都像同一个故事"的担忧在**叙事层不成立**；
- **模板词零残留**：援手/保守秘密/证词/坦白/共同作证/线索推进在正文中
  0 次出现（夜市 1 处"保守秘密"为正常汉语用法，非模板）；
- **贴题度高**：深海（氧气/舱/母船 11 处命中）、夜市（酱料/评比/豆花 14 处），
  叙事围绕用户输入的核心冲突展开（保险柜的信、切口太干净、酱料秘方丢失）。

## 阻塞：30 回合跑不满（模型侧配置，非代码）

qwen3-14b 在该 LM Studio 实例的上下文窗口过小，回合 2~5 即出现
"model narrative was truncated"（502）或 HTTP 400，重试无效——这是**确定性
超窗**，不是偶发。四个题材分别止步于 1/3/3/4 回合。

**恢复条件**：在 LM Studio 把 qwen3-14b 的 Context Length 调到 ≥16K 并重载模型，
然后重跑 `niche_drift_check.py`（request_id 已随机化，可直接重跑）。

## 顺带发现的两个产品问题

1. **Prompt 泄漏**：方言题材回合 1 叙事开头泄漏 "（用中文输出）"、"Start of
   Game"、裸 `<!--DZMM_ACTIONS-->` 标记——`clean_narrative_output` 需要增加
   对这几类 qwen3 风格泄漏的清洗（已知 Qwen 7B 曾有同类问题，14B 换了形态）。
2. **桌面 UI 填表体验**：协议切换会重置已填的 Base URL；AX 自动化下输入易错位
   （人肉影响小，但对自动化测试/无障碍输入不友好）。
