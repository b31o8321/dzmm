## 零、设计前提：用"能力（capability）"承载特殊题材

现有架构已经为特殊题材准备好了挂点：

- `ruleset.enabled_capabilities` 白名单门控（`trpg/combat/resources/chapters/...`），
  引擎命令按能力授权（`_require_capability`）；
- `genre_presets` 骨架参数化（章节名/选择标签/结局标题）已验证四题材互异；
- 契约先行（world_definition / run_state JSON Schema）+ 修复链。

**结论：每个特殊题材模式 = 一个新 capability + 一组新引擎命令 + 一个骨架模板。
不需要推翻任何现有机制，模式之间天然可组合（ruleset 声明启用哪些能力）。**

## 二、需求文档（R）

### R-Loop 死亡循环模式

**用户故事**：
- 作为玩家，我想扮演被困在时间循环中的人：每次死亡或到达"循环终点"，世界回到
  循环开始时的状态，但我保留上一轮的记忆和关键发现，用这些记忆改变这一轮的选择。
- 作为创作者，我在定义世界时声明"循环锚点"（哪些状态属于循环内重置、哪些属于
  玩家跨越循环保留）。

**验收标准**：
1. 循环触发（死亡/到达指定回合/显式命令）时：世界状态回滚到 anchor 快照，
   但 `loop` 计数 +1，且标记为 `loop_knowledge` 的信息保留；
2. NPC 状态回到循环开始（不知道循环），但对话中可引用玩家已保留的知识；
3. 循环计数达到创作者设定的上限时，解锁"真结局"分支（骨架模板支持）；
4. rollback 语义不破坏：正常回合 undo 仍然可用，loop rewind 是独立命令；
5. 契约：run_state 增加 `loop` 节（可选，向后兼容）；
6. 骨架：死亡循环题材模板（章节名"第 N 次循环"、结局标题按循环次数递进）。

**代表性题材**：时间循环推理（只有你知道真相会重置）、末日重来（每次死亡离
拯救更近一步）、无法逃离的宴会（社交循环）。

### R-Countdown 恐怖求生模式

**用户故事**：
- 作为玩家，我面对一个全局倒计时（氧气/时间/理智），每个行动消耗时间，
  某些事件在倒计时低于阈值时必然触发，倒计时归零时进入强制坏结局。
- 作为创作者，我定义倒计时的初值、每行动消耗、阈值触发的事件和归零结局。

**验收标准**：
1. `clock` 状态节：初值、每回合 tick 量、警告阈值；
2. 事件谓词 `clock_below: N` 触发（扩展既有谓词白名单）；
3. clock 归零 → 引擎强制锁定坏结局（`ending-bad` 系）；
4. 某些选择可以回加 clock（找到氧气罐），数值 clamp 到上限；
5. HUD 显示倒计时（战斗结算卡同款组件复用）；
6. 骨架：倒计时题材模板（章节名"氧气还剩 N 天"等）。

**代表性题材**：深空失压（已实测验证题材吸引力）、潜水倒计时、瘟疫封锁、
雪崩掩埋、宴会毒杀倒计时。

## 三、产品方案（P）

### P-Loop 死亡循环

**玩家体验**：
- 开场即"第一次循环"，界面右上角显示「第 N 次循环」徽章（战斗结算卡同款样式）；
- 死亡/循环终点时出现**全屏回环动画卡**：「第 N 次循环结束 → 你保留了 3 条记忆
  → 时间回到X月X日早晨」；
- 循环记忆在游玩页以"你知道但他们不知道"的斜体注记出现在相关叙事下；
- 循环次数达上限后出现新的选项/结局分支（真结局线）。

**创作者体验**：世界定义声明 `loop: { anchor_turn, max_loops, knowledge_flags }`；
AI 草案向导的死亡循环 genre 预设自动生成这套配置。

### P-Countdown 恐怖求生

**玩家体验**：
- 游玩页顶部固定倒计时条（氧气 47:00 → 每回合 -5:00），低于阈值变红并伴随
  事件提示；
- 找到补给时倒计时回加，反馈条显示"+15:00"（复用战斗反馈条组件）；
- 归零时全屏结局卡（坏结局）。

**创作者体验**：世界定义声明 `clock: { initial, tick_per_turn, warn_at, zero_ending_id }`；
灾难求生 genre 预设自动生成。

## 四、技术方案（T）

### T-Loop 死亡循环

1. **契约**：run_state 增加可选 `loop` 节：
   ```json
   "loop": {
     "count": 1,                      // 当前第几次循环（1 起）
     "anchor_state": {...},            // 循环开始时的完整状态快照（引擎管理）
     "knowledge": [ "flag-id", ... ],  // 跨循环保留的 flag/线索 id
     "max_loops": 5                    // 创作者设定，0=无限
   }
   ```
2. **命令**（loop capability 门控）：
   - `start_loop`：compose 后由引擎自动设置 anchor（世界定义含 loop 时）；
   - `rewind_to_anchor`：触发回滚——state 恢复 anchor 快照，`loop.count += 1`，
     保留 `loop.knowledge` 中引用的 flags/events；
3. **触发规则**：世界定义 `loop.trigger` 可选 `"death"`（结局为 bad/hidden 时
   自动 rewind 而非锁定，除非 count > max_loops）/`"turns": N`/`manual`；
4. **记忆分层**：narrative_context 的 recent_turns 在 rewind 时清空（NPC 不记得），
   但 `loop.knowledge` 注入 GM payload 的新字段 `loop_memories`（玩家角色的
   跨循环记忆，供叙事引用）；
5. **骨架**：新 genre 预设 `time_loop`：章节名"第 N 次循环"、结局标题按
   循环递进（`escape` 真结局需 count ≥ max）；
6. **修复链**：弱模型草案含 loop 字段时的剥离/规范化规则。

### T-Countdown 恐怖求生

1. **契约**：run_state 增加可选 `clock` 节：
   ```json
   "clock": { "value": 47, "initial": 60, "tick_per_turn": 5, "warn_at": 15, "unit": "分钟" }
   ```
2. **命令**（countdown capability 门控）：
   - 引擎每回合自动 tick（在 `advance_world_events` 同一位置）；
   - `adjust_clock {delta}`：delta 可正可负，clamp [0, initial]；
3. **谓词扩展**：事件 `trigger`/`completion` 支持 `{"clock_below": N}` /
   `{"clock_above": N}`；
4. **归零结局**：tick 后 value==0 → 引擎直接锁定 `clock_zero_ending`（世界定义
   声明，或回退 bad 结局）；
5. **HUD**：前端 ClockBar 组件（复用反馈条样式）；
6. **修复链**：clock 字段的 clamp 规则。

### 实现顺序

| 里程碑 | 内容 |
|---|---|
| M1 | loop capability（契约+命令+rewind 语义+记忆分层）+ 单测 |
| M2 | countdown capability（契约+tick+谓词扩展+归零结局）+ 单测 |
| M3 | 两个 genre 预设（time_loop / survival_countdown）+ 修复链规则 |
| M4 | 前端：循环徽章/回环动画卡 + ClockBar + HUD 接线 |
| M5 | 双端 30 回合验收（本地模型）+ 合入 main + v1.4.0 发版 |

## 五、风险

- **loop rewind 与 rollback 的交互**：rewind 是新命令而非复用 rollback，避免
  与回合 undo 的 revision 语义纠缠；需要仔细的快照深拷贝测试；
- **记忆分层的契约扩展**：narrative_context.recent_turns 清空时机需与 NPC 记忆
  清理同步，否则 NPC 会"知道"循环；
- **倒计时与章节推进的相互作用**：clock 归零发生在章节中途时，结局锁定优先于
  章节完成判定（需要在 evaluate_endings 前检查）；
- **弱模型对 loop/clock 字段的遵循度**：修复链需要覆盖这两个新结构的形状漂移
  （沿用现有确定性规则模式）。
