## 需求（为什么做）

一局存档的语料厚度（全量 narrative + 每回合 after_state + story_beats）是手写卡的
百倍，但被锁在存档里。竞品两头都空：封闭平台不可导出（Character.AI），开放卡站
内容太薄（chub 卡普遍 <1000 字）。dzmm 的差异化 = **蒸馏**：把游玩历史变成
"角色圣经 / 台词指纹 / 事件年表"，可带走、可再创作（写小说/短剧/开新周目）。

## 产品方案（本版范围）

| 项 | 交付 | 用户可见形态 |
|---|---|---|
| P0 URL 导入 | 粘贴卡片/世界书 URL → 识别格式 → 走现有 ST 导入 | 世界中心「从链接导入」 |
| P0 资产包 v2 | portable bundle 升级：manifest 带 type/license/source_url/version | 导出包字段齐全，可溯源 |
| P1 蒸馏 MVP | 存档 → 后台 LLM 蒸馏 → 角色小传 + 台词样本 + 事件年表（JSON + markdown 导出） | 世界/旅程页「蒸馏这份存档」 |

非目标（本版不做）：市场/账户、源与目录浏览（P3）、hero 跨局复用（P2）、
媒体移植（P4）、关系图（蒸馏 MVP 后续迭代）。

## 技术方案

### P0 URL 导入

- `asset_import.py`：`fetch_and_import(url)` —— urllib 拉取（上限 16MB）→
  Content-Type/内容嗅探（JSON = ST 卡或世界书或资产包；PNG base64 / 二进制 PNG =
  角色卡 PNG）→ 复用 `sillytavern.import_sillytavern` / portable 导入
- 端点：`POST /api/v2/content/assets:import-from-url {url}`（request_id 幂等）
- 安全：SSRF 防护仅允许 http/https；大小上限；失败返回可读错误

### P1 蒸馏 MVP

- 数据流：`POST /runs/{run_id}:distill` → 注册后台任务（复用 ending-closure /
  循环摘要同款 fire-and-forget 模式）→ 读全量 turns.narrative + player_input +
  story_beats → 分段 prompt（角色小传 / 台词指纹 / 年表三个任务，各一次小补全）→
  结果写入新表 `distillations`（run_id, kind, content JSON, created_at）
- 端点：`GET /runs/{run_id}/distillations`（列表）+
  `GET /runs/{run_id}/distillations:export`（markdown 打包：小传 + 台词 + 年表）
- 幂等：同 run 重跑覆盖旧结果；无模型档案时报错提示；任务不阻塞任何回合
- prompt 要点：只依据给定语料、不虚构；台词指纹给出口头禅/句式/情绪→语气样本；
  年表按回合顺序列事件；输出 JSON 由引擎解析修复（失败回退 raw 文本保留）
