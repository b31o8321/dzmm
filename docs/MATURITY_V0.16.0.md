## 结论

v0.16.0 的加权总分为 **88.1/100**，八项均达到本地顺畅使用目标。与本轮开始时约 **58/100** 的基线相比，主要提升来自开放世界事实源统一、状态机规则收口、模型协议防错、失败恢复和 50 回合真实长局验证。

## 真实模型长局证据

验收环境：

- 提供方：LM Studio，OpenAI-compatible `/v1/chat/completions`
- 地址：`http://192.168.31.169:1234/v1`
- 模型：`google/gemma-3-12b`
- 上下文：16K
- 模式：开放世界 framework，多 Agent
- 独立数据库：`/tmp/dzmm-v016-desktop-gemma-final50c.alvJ8v/maturity.db`
- 报告：`/tmp/dzmm-v016-desktop-gemma-final50c.alvJ8v/maturity-report.json`

结果：

- 50/50 回合完成，100 条玩家/GM 消息。
- Director 结构化成功率 20/20，**100%**，高于 95% 目标。
- 标签应用成功率 359/362，**99.17%**，高于 98% 目标。
- 无非法地点、占位地点、非法事件状态和 screenplay 控制记录。
- Campaign 合法推进至第三阶段；`缺页档案`、`市场暗价`、`白塔求救灯` 均完成。
- 故事摘要存在，1361 字；Agent 长历史越过 40 回合后未出现 LM Studio 角色交替错误。
- 首段叙事平均 7.46s；正文平均 27.65s；完整回合平均 32.26s、最大 86.52s。
- 维护平均 4.60s、最大 48.89s。长尾来自每 10 回合一次的摘要压缩，不会破坏回合状态。

## 恢复与操作闭环

50 回合结束后，使用全新 Python 进程重新初始化数据库并通过应用 API 水化：

- `GET /sessions/1`、`GET /sessions/1/messages`、`GET /sessions/1/world_state` 均为 HTTP 200。
- 数据库与 API 均恢复 `turn_count=50`、`message_count=100`。
- 恢复 `pc_location_id=4`、三阶段 Campaign 完成状态和 1361 字故事摘要。

自动化回归覆盖以下交付操作：

- 模型切换前执行健康检查；目标模型失败时返回 422，并保留原模型。
- 429 指数退避后重试成功；HTTP 200 中的协议错误不会误判为健康。
- 撤回恢复回合开始前的状态、Agent 历史和开放世界状态；孤儿失败回合不会误删上一成功回合。
- JSON、Markdown、diagnostics、反馈和 CJK 文件名导出均有接口测试。

## 模型建议

- **默认推荐：** `google/gemma-3-12b`，LM Studio，16K。它在本机 50 回合验收中兼顾首段速度与结构遵循。
- **文风候选：** `magnum-v4-22b`，LM Studio，至少 16K。4K 会因输入超过上下文失败；16K 可运行，但实测首回合约 342.72s，不属于“顺畅使用”的默认配置。
- LM Studio 配置类型必须选 `lm_studio`（或通用 `openai_compat`），Base URL 带 `/v1`。若误选 `ollama`，客户端会调用 `/api/chat`。

## 已知边界与后续提升

- Gemma 偶尔生成不支持的 `investigation` 属性，规则层会拒绝并记录诊断；没有状态污染，但模型提示仍可继续收敛。
- Gemma 偶尔在文本中误判骰子成功，Python 机械层会以真实点数纠正。规则可靠性高于模型语义服从性，二者不应混为一项评分。
- 4/362 个 `choices` 标签发生截断；正文和后续机械标签仍保留，属于可恢复的 P2 诊断。
- 每 10 回合的摘要维护仍有约 35-49s 长尾。下一阶段应优先做异步维护或更轻量的确定性摘要，而不是牺牲状态一致性。
- 当前结论仅覆盖上述推荐模型和本机网络。Magnum 22B、其他本地模型及云端代理需要各自的兼容性采样。
