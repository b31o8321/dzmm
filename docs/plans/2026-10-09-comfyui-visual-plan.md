# v1.11.0 方案：ComfyUI 视觉层——立绘 / 场景插画 / 世界封面

日期：2026-10-09 ｜ 状态：待评审 ｜ 前置：基准图链管线已落地（84caf5e，
comfy_client + visual_pipeline + SDXL 模板 + 单测），本方案补齐
「何时生成、生成什么、在哪配置、UI 挂载、失败与重摇」的完整闭环。

## 一、目标与非目标

目标：
1. 开启视觉功能后，**世界创建 / 主角 / 主要 NPC 创建时自动生成对应图片**，
   支持重摇
2. 游玩回合中按事件自动生成**场景插画**（异步，不阻塞回合）
3. 一致性：基准图链（首次文生图定妆 → 后续图生图延续）
4. 所有图片落盘 `~/.dzmm/media/<world_id>/`，可清理、可导出

非目标（本版不做）：
- 图生视频（生成耗时 2-10 分钟，切入点未定——明确暂缓）
- LoRA 训练（被基准图链替代）
- 手机端独立生图（手机经由后端 HTTP 使用同一管线，端上不直接连 ComfyUI）

## 二、设置模型（两层）

### 2.1 全局视觉设置（设置页新增「视觉」分区）

| 配置 | 默认 | 说明 |
|---|---|---|
| ComfyUI 地址 | http://127.0.0.1:8188 | 手机端填 PC 局域网 IP；带「测试连接」 |
| 视觉功能开关 | 关 | 关闭时全链路零开销（无异步任务、无 payload 变化） |
| 风格前缀 | 内置中文奇幻默认 | 拼接在所有提示词头部；可自定义 |
| 负面提示词 | 内置 | 同上 |
| 工作流覆盖 | 内置 SDXL txt2img/img2img | 可导入 ComfyUI API 格式 JSON 覆盖 |
| 并发上限 | 1 | 同时只排一张，防占满 GPU 影响 LLM |
| 自动生成范围 | 立绘+封面+场景（可分别关） | 场景插画可单独关（省时间） |

存储：`~/.dzmm/visual_settings.json`（非 SQL——纯端侧配置）。

### 2.2 模型档案关联

不做新 provider 类型。视觉服务独立于 LLM 档案（ComfyUI 是图像服务不是
聊天服务）；但世界创建时若选了「自动生成立绘」，需要 LLM 在场生成
appearance 描述卡的**中文外貌文本**（无 LLM 时降级用 description 前段）。

## 三、触发矩阵（何时生成什么）

| 时机 | 生成物 | 方式 | 失败处理 |
|---|---|---|---|
| 世界创建（AI 草案确认） | 每个主要角色**基准立绘**（≤4 张） | LLM 先产出中文外貌卡 → 文生图 | 失败标记 `visual: pending`，卡片显示「重摇」 |
| 世界创建 | **世界封面** ×1 | 世界名+简介 → 文生图 | 同上 |
| 世界创建 | 每个地点**场景基准图**（≤3 张） | 地点描述 → 文生图 | 同上 |
| 主角创建/编辑 | **主角立绘** ×1 | 主角偏好+外貌 → 文生图 | 同上 |
| 回合完成（异步） | **场景插画** ×1 | 在场角色基准图(≤2)做 img2img 参考拼接 + 本回合情境 | 失败静默，不重试 |
| 玩家手动 | 任意图重摇 | 点图上的 🎲 按钮 | — |

时序：立绘/封面在世界创建**之后**异步批量生成（每张 ~10s，4 张 ~40s），
不阻塞「进入游玩」；回合场景插画在回合结算后异步触发，绝对不阻塞下一回合输入。

## 四、数据与 API

### 4.1 契约扩展（可选字段，向后兼容）
- character_cards[i].visual / hero.visual / locations[i].visual:
  `{trigger?, appearance, seed?, ref_image?}`
- ref_image 由服务回填（基准图文件名）；appearance 由 LLM 中文生成

### 4.2 新增 API（全部挂现有后端）
| 端点 | 方法 | 说明 |
|---|---|---|
| /visual/settings | GET/PUT | 视觉设置读写 |
| /visual/status | GET | ComfyUI 可达性 + 队列长度 |
| /visual/generate | POST | {world_id, kind: portrait/location/cover/scene, subject_id, scene_note?} → 异步任务 id |
| /visual/tasks/{id} | GET | 任务状态（queued/running/done/failed + 图片路径） |
| /media/{world_id}/{file} | GET | 图片文件服务 |
| /runs/{id}/turns/{seq}:illustration | POST | 手动为本回合补生成插画 |

### 4.3 视觉注册表
`local_media` 表：id, world_id, kind(portrait/location/cover/scene),
subject_id, turn_seq, file_path, prompt, seed, created_at, status。
重摇 = 同 subject 新 file_path + 覆盖 ref_image 指针（旧图保留可回滚）。

## 五、UI 挂载（手机 + 桌面同源交互）

- **角色卡/地点卡**：有图显示图，无图显示文字卡 + 「生成」/「重摇 🎲」
- **游玩页**：叙事卡顶部横幅插画（16:9，点击放大）；生成中显示占位骨架
- **世界列表**：封面缩略图
- **创建页**：AI 草案审阅区每张卡带「生成立绘」开关（默认开，视觉关闭时隐藏）
- **设置页**：视觉分区（地址/开关/风格/测试连接/并发）

## 六、一致性策略（回应核心诉求）

| 层 | 手段 | 强度 |
|---|---|---|
| 角色 | 基准立绘 → 后续 img2img（denoise 0.5）以基准为参考 | 中-强 |
| 角色（可选加强） | ComfyUI IPAdapter FaceID 节点 + 基准图 | 强（需装节点） |
| 场景 | 场景基准图 + 同 seed 小步进 | 中 |
| 全局 | 统一风格前缀（设置可改，改后全量重摇提示） | 基础 |
| 兜底 | 视觉卡 appearance 固定短语每次原样拼接 | 基础 |

## 七、里程碑拆分（每步可独立交付验证）

- **M1 管线+设置**：comfy_client/visual_pipeline 已有 → 设置分区 +
  visual API + media 表 + 单测（mock HTTP）。约 1 个迭代日
- **M2 触发闭环**：世界创建/回合完成的异步触发 + 重摇 API + 失败标记。
  约 1 个迭代日
- **M3 UI 挂载**：桌面+手机的角色卡/游玩页/列表封面。约 1-1.5 迭代日
- **M4 真机联调**：PC ComfyUI --listen 暴露 → 手机跨网生成实测

## 八、风险与开放问题

1. **首图依赖**：基准立绘不满意需重摇（10s 可接受）；IPAdapter 为后续增强
2. **GPU 争抢**：ComfyUI 生图时 Ollama LLM 会等待——并发上限 1 + 异步错峰
   （回合结算后再排图）已缓解；极端情况玩家可关场景插画
3. **磁盘**：PNG 每张 1-2MB，长会话百张图 ~200MB——media 目录可整删可导出
4. **开放问题**： appearance 中文卡直接拼提示词 vs 翻译成英文标签——
   建议第一版「中文描述 + 风格前缀英文」混合（SDXL 中文理解可用），
   效果不满意再引入翻译层
