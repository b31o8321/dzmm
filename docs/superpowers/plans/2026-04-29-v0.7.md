# v0.7 Implementation Plan — 沉浸感 + 长线持续 + NPC 攻略

> Use superpowers:subagent-driven-development.

**Theme:** Less engineering plumbing, more "actually fun while playing". Five gameplay features (journal, NPC attraction details, XP, BGM, portraits) balanced with two perf items (summary recursion, model warmup).

**Why this mix:**
- v0.5 / v0.6 finished the durability / packaging / mobile baseline
- The tooling is now stable enough to move "up the stack" toward what makes a TRPG / ACG-flavored session memorable: progression, atmosphere, visualizing your world, **and tracking attraction targets across multiple affinity axes** (the same way a dating-sim or visual novel does)
- Two perf items keep long sessions playable: recursive summary compression (no context overflow at hour 3) + model warmup (no 5-10s wait on first turn)

**`<npc_update>` extended schema** (backward compatible — old fields still work):

```xml
<npc_update>
{
  "name": "御坂雪",
  "favor_delta": +5,
  "affinity": {"信任": +3, "羁绊": +2},
  "state": "对你敞开了一些心扉",
  "purpose": "查清祖母遗物里咒符的来源",
  "archetype": "外柔内刚的文学少女",
  "description": "21 岁，早大学生，目击过祖母禳灾仪式",
  "note": "在浅草庙会上分享了童年阴影"
}
```

`affinity` is a partial-update map: each axis adds its delta to the stored `affinity_json[axis]` (creating the axis if missing). `favor_delta` continues to update the legacy single-axis `favor` field for backward compat.

`purpose` and `archetype` are setters (overwritten on each update if present, else preserved).

In `db/base.py` `init_db`, add a migration helper that uses SQLite's `PRAGMA table_info(npcs)` to detect missing columns and `ALTER TABLE` them in place. This pattern then reused by Task A4 (portraits) and B2 (XP).

```python
async def _migrate_add_columns(conn, table: str, columns: list[tuple[str, str]]) -> None:
    rows = await conn.exec_driver_sql(f"PRAGMA table_info({table})")
    existing = {r[1] for r in rows.fetchall()}
    for name, ddl in columns:
        if name not in existing:
            await conn.exec_driver_sql(f"ALTER TABLE {table} ADD COLUMN {ddl}")

# called from init_db after create_all:
await _migrate_add_columns(conn, "npcs", [
    ("purpose", "purpose TEXT NOT NULL DEFAULT ''"),
    ("archetype", "archetype VARCHAR(120) NOT NULL DEFAULT ''"),
    ("affinity_json", "affinity_json TEXT NOT NULL DEFAULT '{}'"),
])
```

- [ ] **Step 2: extend `_apply_npc_update`**

```python
async def _apply_npc_update(...):
    payload = parse_loose_json(raw)
    name = payload.get("name")
    if not name: return

    npc = ... (existing lookup or create)

    # Existing fields
    favor_delta = payload.get("favor_delta", 0)
    if isinstance(favor_delta, (int, float)):
        npc.favor += int(favor_delta)
    if "state" in payload: npc.state = str(payload["state"])
    if "description" in payload and not npc.description:
        npc.description = str(payload["description"])

    # NEW: purpose, archetype (overwrite if provided)
    if "purpose" in payload:
        npc.purpose = str(payload["purpose"])
    if "archetype" in payload:
        npc.archetype = str(payload["archetype"])

    # NEW: multi-axis affinity (additive)
    if "affinity" in payload and isinstance(payload["affinity"], dict):
        affinity = json.loads(npc.affinity_json or "{}")
        for axis, delta in payload["affinity"].items():
            if isinstance(delta, (int, float)):
                affinity[axis] = int(affinity.get(axis, 0) + delta)
        npc.affinity_json = json.dumps(affinity, ensure_ascii=False)

    # ... existing note + last_seen_turn update
```

```python
@router.get("/{session_id}/npcs")
async def get_npcs(session_id: int, s: AsyncSession = Depends(get_session_dep)):
    sess = await s.get(GameSession, session_id)
    if sess is None:
        raise HTTPException(404, "session not found")
    rows = (await s.execute(
        select(NPC).where(NPC.session_id == session_id)
        .order_by(NPC.last_seen_turn.desc())
    )).scalars().all()
    return [
        {
            "id": n.id,
            "name": n.name,
            "description": n.description,
            "favor": n.favor,
            "state": n.state,
            "purpose": n.purpose,
            "archetype": n.archetype,
            "affinity": json.loads(n.affinity_json or "{}"),
            "notes": json.loads(n.notes_json or "[]"),
            "last_seen_turn": n.last_seen_turn,
        }
        for n in rows
    ]
```

**Goal:** GM can award XP via `<character_xp delta="50">解决了卫兵的盘问</character_xp>`. When current XP crosses level threshold (level 1 → 2 at 100, 2 → 3 at 250, 3 → 4 at 500, etc), frontend pops a dialog letting the player pick which base stat to increment by 1 (or +5 if HP/stamina). Level becomes part of character card injected into next prompt so GM knows the PC has grown.

XP formula: `xp_to_next_level(n) = 100 * n * (n+1) / 2` (n=1: 100, n=2: 300, n=3: 600).

- [ ] Schema migration adds `xp INT DEFAULT 0`, `level INT DEFAULT 1` columns.
- [ ] `<character_xp>` tag handled in state_apply (similar to npc_update); tests cover positive delta and threshold crossing.
- [ ] gm_template adds the tag to behavior section: "完成关键任务、克服重大挑战、大成功的判定时给 XP（典型 10-50）"; injected character card includes current level.
- [ ] Frontend XP bar in GameView header showing current/threshold; when threshold crossed locally (after applying tag), pop LevelUpDialog asking which stat.
- [ ] Backend `POST /characters/{id}/levelup` body: `{stat: string, amount: number}`. Updates `base_stats_json`. Also auto-syncs CharState if session is active.

### Task B5: Recursive summary compression

**Goal:** When summary itself exceeds 1500 tokens, run a "compress-only" call that:

For v0.7, just persist timeline; surfacing UI is v0.8.
