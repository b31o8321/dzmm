## v1.7.0「资产生态启程」——主题：把游玩历史变成资产

依据 `docs/plans/2026-09-28-asset-ecosystem-matrix.md`（sess_82932ae8 收敛稿）评估：

### 评估结论：放 1.7.0，且只放 P0+P1

- **不放 1.6.0 的理由**：1.6.0 已背 UI 重设计实施（本版最大风险项）+ 试玩场 +
  两分支合入；资产生态是"未立项"状态，按两阶段流程还需要需求/产品/技术方案稿，
  塞进 1.6.0 会稀释发布质量。
- **放 1.7.0 的范围**：
  - **P0 容器与入口**（矩阵自评"小活"）：资产包 schema v2（L1 设定/L2 语料/L3 表现
    三层 + license）+ B6 打包升级 + C2 URL/文件导入一等公民
  - **P1 蒸馏 MVP**（矩阵定位"灵魂"，dzmm 独有差异化）：真实存档 → 角色小传 +
    台词指纹 + 事件年表；复用 1.5.0/1.6.0 已落地的后台 LLM 任务模式
    （ending-closure/循环摘要同款 fire-and-forget）
- **P2 出口与复用（小说/短剧素材、hero 跨局）→ 1.8.0**；P3 分发（源/目录）→ 1.9.0；
  P4 媒体（TTS/立绘移植）→ 2.0 前夕。

### 时序红利（为什么蒸馏放 1.7.0 反而更好）

1. 1.6.0 的循环题材 + 试玩场会产出更丰富的游玩语料，蒸馏 MVP 有真料可蒸馏
2. 蒸馏管线与循环摘要/结局收束共用后台任务基建，1.6.0 合入后该模式经三次实战验证
3. 矩阵 5 个开放问题（hero 继承/模型路径/源托管/schema 严谨度/隐私边界）可在
  1.6.0 实施期并行拍板，不阻塞开工

### 需用户拍板的开放问题（1.7.0 立项前，不急）

① hero 跨局继承策略；② 蒸馏模型路径（建议：可配置管道，MVP 用用户已有模型配置）；
③ 官方源托管（建议：jsDelivr 镜像起步）；④ 蒸馏产物 schema 严谨度；⑤ L2 语料隐私边界。
