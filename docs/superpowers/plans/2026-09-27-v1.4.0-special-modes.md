# DZMM v1.4.0 规划：时间系统 + 记忆基建 + 循环/倒计时双模式（需求 / 产品 / 技术）

日期：2026-09-27（v2，按维护者反馈调整）
状态：Confirmed（方案已确认，按 M0→M5 实现）
分支：`feature/v1.4.0-special-modes`
前置：v1.3.0（结局 genre 化、反惯性、战斗结算卡、Director 可见化、192 tests）

---

## 零、v2 调整摘要（相对初版）

1. **时间系统提为通用底座**：行动耗时 + 时钟推进不再只属于倒计时/循环，
   而是一层通用能力（任何题材都可声明时间制）；
2. **记忆三层基建（M0）前置为硬依赖**：循环类对长期记忆的压力（context 膨胀、
   NPC 记忆污染、摘要不区分循环）决定了没有分层记忆就不能上循环——且该基建
   对普通长局/RAG/Director 均有益；
3. **死亡循环提前为 1.4.0 头牌**（维护者判断：循环类最适合 LLM 发挥——
   "同一场景、不同信息"的重演是 LLM 强项，且循环锚点天然抑制跑偏累积）；
   前提是 M0 完成；
4. **倒计时降为时间系统的预设**（clock 单调递减 + 归零结局），不再是独立机制。

---

## 一、需求（R）

### R-Time 时间系统（通用底座）

**用户故事**：
- 作为玩家，我的每个行动都有时间代价：侦查线索花 2 小时、陪 NPC 聊天花 1 小时、
  赶路花 30 分钟——时间成为与 HP 并列的第二资源；
- 作为玩家，我能看到当前时间（ClockBar），理解"今天还剩几个小时"。

**验收标准**：
1. 世界定义声明时间制：`{ start_minutes, loop_at_minutes, per_turn_max_minutes, unit }`；
2. 行动耗时由模型提议（gm_actions 白名单新增 `propose_time_cost { minutes, reason }`），
   Python 引擎裁决（clamp [0, per_turn_max]，无提议时默认消耗 30 分钟）；
3. 时钟在回合结算时推进，HUD（ClockBar）实时显示；
4. 时钟到达 `loop_at` 时触发世界定义声明的行为（循环回环/倒计时归零/无事发生）；
5. 契约：run_state 增加可选 `clock` 节 `{ now_minutes, start_minutes, loop_at_minutes, day }`；
6. 弱模型修复链：propose_time_cost 形状漂移的确定性剥离/clamp。

### R-Loop 死亡循环模式（1.4.0 头牌，LLM 主场）

**用户故事**：
- 作为玩家，我被困在时间循环中：时钟到 loop_at 自动回环（死亡可提前触发），
  世界回到循环锚点，但我保留跨循环记忆——用"只有我知道的信息"改变这一轮。
- 作为玩家，我想看到 NPC 每轮循环的微妙差异（他们不知道循环，但氛围/情绪随
  循环次数变化）。
- 作为维护者，循环类对 LLM 的跑偏容忍度是所有玩法里最高的（锚点每轮回拉），
  我要用 30 回合实测验证"重演质量"这个 LLM 核心能力。

**验收标准**：
1. 时钟到 `loop_at` → 引擎自动 `rewind_to_anchor`：世界状态恢复锚点快照，
   `loop.count += 1`，跨循环知识保留；
2. 死亡（结局 kind=bad/hidden 且世界声明 `loop.trigger` 含 "death"）→ 提前触发
   rewind 而非锁定（除非 count ≥ max_loops，此时锁定真结局线）；
3. **记忆分层**（M0 基建）：rewind 时循环内记忆清空（recent_turns/NPC 状态/
   dialogues），跨循环知识（引擎白名单管理的 loop_knowledge）保留并注入 GM
   payload 独立字段 `loop_memories`；
4. 分段摘要：每个循环结束时生成该循环的 200 字摘要（独立于全局摘要），
   注入 GM payload `loop_summaries`；
5. 循环递进结局：count ≥ max_loops 后新增可选结局分支（骨架模板支持）；
6. NPC 微妙差异：GM payload 增加 `loop.count`，system prompt 指示"NPC 不知道
   循环，但叙事可以让氛围随循环次数微妙变化"；
7. 契约：run_state 增加可选 `loop` 节；修复链覆盖 loop 字段形状漂移。

### R-Countdown 恐怖求生模式（时间系统的预设）

**验收标准**：
1. `clock` 节扩展 `countdown: { tick_per_turn, warn_at }`：每回合单调递减；
2. 事件谓词 `clock_below: N` 触发；
3. 归零 → 引擎锁定坏结局（世界定义可声明专属 zero 结局）；
4. 找到补给 `adjust_clock {delta}` 回加（clamp [0, initial]），反馈条显示
   "+15 分钟"；
5. 骨架：倒计时题材章节名模板（"氧气还剩 N"）。

### R-M0 记忆三层基建（硬依赖，先于 loop）

| 层 | 内容 | 生命周期 |
|---|---|---|
| 循环内记忆（ephemeral） | 现有 recent_turns / npc_state / dialogues | rewind 时清空 |
| 跨循环知识（persistent） | 新增 `loop_knowledge`：仅通过引擎白名单命令写入（discover/learn），结构化 {id, text, discovered_turn} | rewind 保留；仅在声明 loop 的世界激活 |
| 分段摘要（per-loop summary） | 每次循环结束生成该循环 200 字摘要 | rewind 时追加到 loop_summaries；注入 GM payload |

### R-Walkthrough Tauri 窗口可见走查（gate 遗留，等屏幕解锁）

## 二、产品方案（P）

### P-Time ClockBar

- 游玩页顶部固定时间条：`第 1 天 · 09:30`（行动后动画推进到新时间）；
- 距 loop_at 不足 2 小时：时间条变琥珀色 + "今天即将结束"提示；
- 手机版：时间条压缩为章节栏右侧一枚时间徽章。

### P-Loop 循环体验

- 右上角循环徽章：「第 N 次循环」（结算卡同款样式）；
- 回环时全屏动画卡：「第 N 次循环结束 → 你带走了 3 条记忆 → 时间回到 06:00」，
  列出保留的 loop_knowledge 条目；
- "你知道但他们不知道"：相关叙事下以斜体注记展示对应 loop_knowledge；
- count ≥ max_loops：徽章变金色，新增真结局线选项。

### P-Countdown 倒计时体验

- ClockBar 单调递减，warn_at 以下变红 + 事件提示；
- 补给回加显示"+15 分钟"反馈（复用反馈条）；
- 归零全屏坏结局卡。

### P-Director（1.3.0 遗留收尾）

- 设置 → 高级诊断：Director 注释折叠区（最近+历史）+ 开关；
- 长局评估脚本 director_audit.py（turn/tension/hook/叙事四元组导出）。

## 三、技术方案（T）

### T0 记忆三层基建

1. 契约：run_state 增加可选 `loop_knowledge: [{id, text, discovered_turn}]`
   与 `loop_summaries: [{loop_no, summary}]`（均为可选，向后兼容）；
2. 引擎命令（loop capability 门控；非 loop 世界由创作者按需启用 discovery）：
   `discover {id, text}`：写入 loop_knowledge（去重、text 长度 clamp 200）；
3. rewind 语义（loop 世界）：state = anchor 快照 → 恢复循环内状态；
   loop_knowledge/loop_summaries 从快照外合并回来；narrative_context 清空；
4. 分段摘要：rewind 时后台 daemon 调模型生成该循环摘要（复用 ending closure
   的 fire-and-forget 模式）；
5. 注入：GM payload 新增 `loop_memories`（knowledge 条目）与
   `loop_summaries`（前 N 循环摘要）；非 loop 世界为空数组，prompt 注明忽略。

### T1 时间系统

1. 契约：run_state 增加可选 `clock` 节
   `{ now_minutes, start_minutes, loop_at_minutes, day, per_turn_max, unit }`；
2. world_definition 增加可选 `time_system` 声明；
3. gm_actions 白名单新增 `propose_time_cost {minutes, reason}`：引擎 clamp
   [0, per_turn_max]，应用后推进 `now_minutes`，跨日 `day += 1`；
4. `advance_world_events` 同一位置：now ≥ loop_at 时按世界声明触发
   （loop 世界 → rewind；countdown 世界 → 本字段不适用）；
5. HUD：ClockBar（桌面+手机）；
6. 修复链：propose_time_cost 缺失/越界/非数值的确定性处理。

### T2 Loop capability

1. 契约：run_state 增加可选 `loop` 节
   `{ count, max_loops, anchor_state, knowledge_ids }`（anchor_state 引擎管理，
   不进 GM payload）；
2. world_definition 增加可选 `loop_config { trigger: ["time"|"death"],
   max_loops, knowledge_whitelist_hint }`；
3. `rewind_to_anchor` 命令（loop capability 门控）：深拷贝恢复 + 知识合并 +
   记忆清空 + count 递增 + 分段摘要触发；
4. 死亡触发：evaluate_endings 锁定 kind∈{bad,hidden} 且 count < max_loops
   且 trigger 含 "death" → 不锁定，改触发 rewind（结局卡替换为回环卡）；
5. count ≥ max_loops：解锁骨架声明的真结局分支（choices 追加）；
6. system prompt：loop.count 注入 + "NPC 不知道循环"指示 + loop_memories
   使用说明；
7. 修复链：loop/clock 字段形状漂移规则。

### T3 Countdown（时间系统预设）

1. clock 声明含 `countdown: {tick_per_turn, warn_at, zero_ending}`；
2. tick 逻辑：每回合 now 推进固定 tick（无 propose_time_cost 覆盖）；
3. 谓词扩展：`clock_below` / `clock_above`；
4. 归零：锁定 zero_ending（缺省回退 ending-bad 系）；
5. `adjust_clock {delta}` 命令。

### T4 前端

1. ClockBar（桌面+手机徽章）；
2. 循环徽章 + 回环动画卡（列出保留知识）；
3. "你知道但他们不知道"斜体注记；
4. Director 面板（1.3.0 遗留收尾：设置折叠区）。

### 测试策略

| 层 | 用例 |
|---|---|
| 单测 | time 推进/跨日/clamp；rewind 快照恢复+知识合并+记忆清空；死亡触发 rewind vs 锁定；count ≥ max 真结局解锁；clock_below 谓词；归零结局；修复链新规则 |
| 契约 | clock/loop/loop_knowledge/loop_summaries 全量 validate + 向后兼容（旧存档无这些字段） |

## 四、风险

1. **rewind 快照深度**：anchor_state 需完整深拷贝（含 npc_state/emotion/关系），
   漏一层就是"NPC 记得循环"事故——单测必须逐字段断言；
2. **分段摘要延迟**：rewind 后摘要后台生成有窗口期，GM payload 需容忍缺失
   （fire-and-forget，与 Director 同模式）；
3. **prompt 长度**：loop_memories + loop_summaries + recent_openings 叠加，
   32K 上下文预算需监控（超限时 summaries 只带最近 2 条）；
4. **7B 模型对"NPC 不知道循环"的遵循度**：验收脚本需含 NPC 泄密检测
   （叙事中 NPC 引用循环内信息即记缺陷）。
