系统层可玩性：RPG 内容维度评估地图与增强计划

依据：本机 7B × 120 回合全量数据（eval/score-upgrade/local7b-120run-report.json）+ 引擎代码取证 · 2026-09-30 · 结论先行：引擎有 7 个系统，模型只驱动了 2 个——本方案补齐写路径、裁决与世界触发器，并建立 12 维评估体系。

① 120 回合证据回顾（为什么这个版本要做这个）

120/120回合零失败（稳定性达标）

③ 增强方案：三支柱（全部沿用「模型提议 → 引擎裁决 → 限幅审计」既有模式）

支柱 A · P0

模型写路径扩展（gm_actions v2）——解决「模型不能动系统层」的根因

现有 gm_actions 只能写剧情线/隐藏事件/声誉。新增两个提案类型，引擎全权裁决：

提案类型payload引擎裁决规则
propose_inventory_change{item_id, delta, reason_key}item_id 必须在世界 resources 白名单；delta ∈ [-3,+3]；净存量 ≥0；每回合 ≤1 次
propose_skill_check{skill, dc, target, reason_key}skill ∈ 世界声明清单；DC 5–25；引擎掷 d20+调整值 → 成功/失败 outcome 交给模型叙事

配套：NARRATIVE_SYSTEM_PROMPT 增补两个提案的使用时机说明；outcome 新类型进 TurnResult（无契约破坏——outcomes 为自由 JSON）。7B/14B 遵循率入评估（弱模型不用也不劣化现状）。

支柱 B · P0

引擎裁决扩展——技能检定 + NPC 主动性可见化

skill_check 机制：世界 ruleset 声明技能清单（潜行/说服/察觉…），hero/NC 携带调整值；引擎侧 apply_skill_check(state, definition, payload) 掷 d20+调整值 vs DC，产出成功等级（大成功/成功/失败/大失败），失败可挂状态效果（P2 扩展）。

NPC 主动性可见化：pending_interactions 已调度即写入 GM payload 独立块（含 NPC 名与 instruction），并要求模型在叙事中以该 NPC 主动开口开场；UI 侧 PlayScene 增加「{{npc}} 想找你」提示条；评估增加「主动性演绎率」指标（调度→可见对白的转化）。

对白格式锚定：GM payload 按在场 NPC 附一句格式示例（『海爷低声说：「……」』），清洗规则对「名字：」行内冒号式做重排告警。

任务系统（带奖励）：世界定义 story.quests：{id, title, completion:{flag}, rewards:[{type: item|clue|skill, ...}]}。flag 翻转 → 引擎自动标记完成并发放奖励（item 进背包走资源白名单限幅；clue 注入新剧情线；skill 加入 hero 技能集供检定）。每任务奖励仅发一次，outcome 留审计。

支柱 C · P1

世界模板与评估体系——让系统被点亮、被度量

模板注入：三大模板世界默认携带遭遇战配置（敌对 NPC + 战斗规则）、道具拾取点（resources 布点）、NPC 主动性参数、技能清单与 DC 建议。

全动作驱动脚本（评估核心）：thematic_run.py 升级为混合动作模式——narrate 60% / move 15% / roll 或 skill_check 10% / inventory 10% / choose 5%，按回合比例轮换；新增 12 维指标采集（地点覆盖、战斗次数与结果分布、道具净流、声誉/关系变化、事件闭环率、主动性演绎率、任务完成率、记忆矛盾数）。

验收方式：7B 与 GPT-5.6 各跑 120 回合全动作对照——期望两模型都能点亮 ≥8/12 维度，GPT 5.6 零引擎失败。

⑤ 风险与非目标

风险与对策

风险对策
弱模型滥用新写路径（乱给道具/乱掷骰）引擎限幅 + 白名单 + 每回合次数上限；滥用进 outcomes 审计
GM payload 再膨胀新增块走预算（技能清单/示例各 ≤200 字），不突破 ~4k 上限
