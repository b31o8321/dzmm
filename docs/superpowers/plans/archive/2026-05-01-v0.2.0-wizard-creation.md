# v0.2.0 向导式世界 + 角色 + 剧本创建（Vibe Coding 风格）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` to implement task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 替代当前一次性 outline LLM 调用，改成 **6 步引导式生成**：每一步玩家审阅 → 编辑 / 重新生成 / 接受 → 下一步。优化目标：本地 12B 模型也能稳定产出有质感的世界 + 角色 + 剧本，而不是一次性生成的简陋版本。

**Architecture:** 后端 stateless 多端点（每步独立 LLM 调用，短 prompt 单任务），前端 stepper UI 保存中间状态在 reactive 变量（不存临时表，关页面即失），最后 finalize 时一次性 atomic 写 World + Character + Screenplay 三张表 + 跳转 /play/:id。

**Tech Stack:** Python FastAPI 端点（每步 ~30-60s LLM 调用），Vue 3 stepper 组件，Pinia 暂存（可选）。

## 设计决策（待用户对齐）

需要 user 确认下面 8 点：

1. **步骤数量**：6 步合适？还是切成 4 大步？我的建议 6 步（基础设定 / 世界 / PC / NPC / 剧本 / 审阅），太少每步还是太重。
2. **可否跳步**：先生成全部再调整？还是必须按顺序逐步？建议**逐步**（后步骤依赖前步骤的内容），但允许「返回上一步」。
3. **每步可否手写跳过 LLM**：玩家可不可以直接 paste 自己写的 world_md？建议**可以**——在每步加「我自己写」选项。
4. **wizard 模型 vs GM 模型**：用户提了——是否分开选？建议「在 step 1 让玩家选 wizard model + GM model 两个配置」。wizard 可以用 think 模型（qwen2.5:14b / deepseek-r1），GM 用快的 7b。
5. **NPC 是否在 wizard 里就建表**：还是只生成 NPC bundle 给 GM 当参考、跑团时按需建？建议**先生成 + 玩家选「钉住」哪几个，钉住的写 NPC 表（pinned=true），其它只作为剧本 main_characters 参考**。
6. **是否预览整体 token 消耗**：每步 LLM 调用大约 500-2000 token。要不要在最后一步显示总 cost 估算？stretch goal，先不做。
7. **是否保留「快速创建」选项**：当前 SessionsView 选预设 world + character + 一键生成 outline 还要保留吗？建议**保留**——不熟悉系统的玩家直接用预设；wizard 是高级玩法。
8. **失败处理**：第 5 步剧本生成失败时，玩家能不能基于已有 world / character 重新生成？建议**可以**——每步都是独立调用，失败不影响前面。

```python
import pytest
from collections.abc import AsyncIterator
from dzmm.models.client import (
    GenerationParams, Message, ModelClient, StreamChunk, TokenUsage,
)
from dzmm.service.wizard import generate_world_brief


class StubLLM(ModelClient):
    name = "stub"
    def __init__(self, output: str): self.output = output
    async def stream(self, msgs, params) -> AsyncIterator[StreamChunk]:
        yield StreamChunk(delta=self.output)
        yield StreamChunk(delta="", finish_reason="stop",
                          usage=TokenUsage(input_tokens=20, output_tokens=80))


async def test_world_brief_basic_shape():
    """World brief returns name + setting + tone summary in 100-300 chars."""
    stub_output = """## 名字
新月之城

## 年代与地点
21 世纪末的香港，气候巨变后被海水淹没大半。

## 核心冲突
义体黑客与企业政府的猫鼠博弈。
"""
    client = StubLLM(stub_output)
    result = await generate_world_brief(
        genre="赛博朋克",
        theme="义体黑客对抗超国家公司",
        client=client,
    )
    assert "新月之城" in result["name"]
    assert "21 世纪末" in result["setting"]
    assert "义体黑客" in result["conflict"]
    assert len(result["raw_md"]) >= 100


async def test_world_brief_uses_genre_and_theme_in_prompt():
    """The LLM call should embed both user inputs in the user message."""
    captured: list = []

    class Spy(StubLLM):
        async def stream(self, msgs, params):
            captured.extend(msgs)
            async for x in super().stream(msgs, params):
                yield x

    await generate_world_brief(
        genre="奇幻",
        theme="精灵在末日中寻找最后的图书馆",
        client=Spy("## 名字\n图书馆\n## 年代与地点\nx\n## 核心冲突\nx"),
    )
    user_text = next(m.content for m in captured if m.role == "user")
    assert "奇幻" in user_text
    assert "图书馆" in user_text or "精灵" in user_text
```

```python
"""v0.2.0 wizard step 1: world brief — 100-300 字基础设定（名字 / 年代 / 核心冲突）。

用本地 12B 模型友好的短 prompt + 严格 markdown 格式输出。
后续 step 2 (world details) 基于这个 brief 扩展。
"""
from dzmm.models.client import Message


_SYSTEM = """你是 TRPG 世界观设计师。根据玩家给的 genre + 一句话主题，
生成一个 100-300 字的世界基础设定。

# 输出格式（严格 markdown，三段）

## 名字
（世界 / 城市 / 大陆 / 时代 的名字，3-8 字）

## 年代与地点
（一句话：时空背景 + 主要场景类型）

## 核心冲突
（一句话：玩家进入这个世界要面对的根本张力）

# 设计原则
- 简练。不要写小说式描述。
- 名字要好记，避免 5 字以上长名。
- 核心冲突要让玩家直觉「我能在这里做事」。
- 不输出任何标题之外的 markdown 格式。
"""


def build_world_brief_messages(genre: str, theme: str) -> list[Message]:
    return [
        Message(role="system", content=_SYSTEM),
        Message(role="user", content=(
            f"# 类型\n{genre}\n\n"
            f"# 主题\n{theme}\n\n"
            "现在生成世界基础设定的 markdown。"
        )),
    ]
```

- [ ] **Step 4: 写 service**

`backend/src/dzmm/service/wizard.py`:
```python
"""v0.2.0 wizard service — 多步骤世界 / 角色 / 剧本生成的业务逻辑。

每个函数一次 LLM 调用 + 解析结果，返回结构化 dict 供前端展示。
状态在前端保存（不存后端临时表），finalize_wizard 时 atomic 写 DB。
"""
import re
from dzmm.models.client import GenerationParams, ModelClient
from dzmm.prompts.wizard_world_brief import build_world_brief_messages


def _parse_section(md: str, header: str) -> str:
    """Extract content after `## {header}` until next `##` or EOF."""
    pat = re.compile(rf"^##\s*{re.escape(header)}\s*$([^#]*)", re.MULTILINE)
    m = pat.search(md)
    return (m.group(1).strip() if m else "")


async def generate_world_brief(
    genre: str,
    theme: str,
    client: ModelClient,
) -> dict:
    """Step 1: world brief. Returns {name, setting, conflict, raw_md}."""
    messages = build_world_brief_messages(genre, theme)
    chunks: list[str] = []
    async for chunk in client.stream(
        messages, GenerationParams(max_tokens=600, temperature=0.85),
    ):
        if chunk.delta:
            chunks.append(chunk.delta)
    raw = "".join(chunks).strip()

    return {
        "name": _parse_section(raw, "名字"),
        "setting": _parse_section(raw, "年代与地点"),
        "conflict": _parse_section(raw, "核心冲突"),
        "raw_md": raw,
    }
```

## 风险 + 注意事项

1. **每步 LLM 失败处理** —— Step 5 之前任何步骤失败都不影响 DB；只有 finalize 是原子的。
2. **本地 12B 模型生成质量** —— prompt 要短小聚焦。每个 step prompt 应该 < 500 token，max_tokens < 1500。
3. **wizard 期间玩家关页面** —— 中间状态丢失（只在 reactive 里）。可加 localStorage 持久但 stretch。
4. **wizard 总耗时** —— 6 步 LLM 各 30-60s = 3-6 分钟。比一次性长，但每步短。要在每步显示「⏳ 生成中... Xs / 通常 30-60s」减缓焦虑。
5. **手写跳过 LLM 选项** —— 让玩家可以 bypass。重要性：当前已有的预设世界/角色就是「手写跳过 LLM」的 v1。wizard 在这个之上提供「LLM 协助 + 玩家逐步精修」。
